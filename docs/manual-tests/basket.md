# Ручные smoke-тесты корзины Omega

## Общие предусловия

- Пользователь авторизован в выбранной среде, открыт раздел `Кошик` (`#/app/basket`).
- Корзина разделена на две секции: `Товари зі складу` и `Товари під замовлення`.
  Товар попадает в одну из них в зависимости от наличия — искать строку нужно
  с учётом секции.
- Панель добавления состоит из поля `Додати позицію`, счётчика количества
  с кнопками `−` / `+` и кнопки подтверждения. **Количество задаётся до добавления.**
- Клиент общий: в корзине могут лежать чужие позиции. Каждый сценарий,
  добавляющий товар, обязан удалить за собой только то, что добавил.

## Тестовые данные

Один товар адресуется двумя идентификаторами — это используется в BASKET-003.

| Идентификатор | Значение |
|---|---|
| Номер карточки | `4610495` |
| Каталожный код | `OC90` |
| Название | Фільтр оливний LANOS, AVEO, LACETTI, NUBIRA, NEXIA (вир-во KNECHT-MAHLE) |
| Производитель | KNECHT/MAHLE |
| Несуществующий запрос | `zz-no-product-987654321` |

**Цена товара меняется со временем** (наблюдались `111.30`, `130.06`, `159.06`).
Ни один сценарий не сверяет цену с константой — проверяется только положительность
и арифметика «цена × количество = сумма».

## Корзина — P0

### BASKET-001. Открытие корзины

**Предусловие:** пользователь авторизован.

1. Открыть раздел `Кошик`.

**Ожидаемый результат:** страница загрузилась; доступны поле `Додати позицію`,
счётчик количества и кнопка подтверждения; виден переход в `Журнал рахунків`.
При пустой корзине обе секции показывают
`Кошик ще порожній, скористайтеся пошуком для додавання товарів` и
`Кошик під замовлення ще порожній, скористайтеся пошуком для додавання товарів`.

### BASKET-002. Добавление по номеру карточки

**Предусловие:** товара `4610495` в корзине нет.

1. Ввести `4610495` в поле `Додати позицію`.
2. Убедиться, что счётчик количества равен `1`.
3. Нажать кнопку подтверждения.

**Ожидаемый результат:** товар добавлен ровно одной строкой; в строке видны
код `OC90`, карточка `4610495`, название и производитель; количество `1`;
цена больше нуля. Появляется тост `Кошик / Товар був доданий <название>`.

**Уборка:** удалить добавленную строку; состав остальных строк не изменился.

### BASKET-003. Каталожный код не создаёт дубль

**Предусловие:** товара `4610495` в корзине нет.

1. Добавить `4610495` с количеством `1`.
2. Ввести в то же поле каталожный код `OC90`.
3. Оставить количество `1` и нажать подтверждение.

**Ожидаемый результат:** поле принимает оба идентификатора. Вторая строка
**не создаётся** — количество в существующей строке растёт с `1` до `2`,
общее число строк корзины не меняется.

**Уборка:** удалить добавленную строку.

### BASKET-004. Добавление заданного количества сразу

**Предусловие:** товара `4610495` в корзине нет.

1. Ввести `4610495` в поле добавления.
2. Нажать `+` дважды — счётчик показывает `3`.
3. Нажать подтверждение.

**Ожидаемый результат:** товар добавлен **одной строкой сразу с количеством `3`**,
а не с `1`. Сумма выбранных равна цене, умноженной на три.

**Уборка:** удалить добавленную строку.

### BASKET-005. Добавленная позиция отмечается автоматически

**Предусловие:** корзина пуста.

1. Добавить `4610495` с количеством `1`.
2. Осмотреть чекбокс в строке товара и значение `Загальна сума обраних в кошику`.

**Ожидаемый результат:** чекбокс строки **уже отмечен**, отдельный клик не нужен;
сумма выбранных равна цене товара.

**Уборка:** удалить добавленную строку.

### BASKET-006. Панель добавления не сбрасывается

**Предусловие:** товара `4610495` в корзине нет.

1. Ввести `4610495`, установить счётчик в `3`, подтвердить.
2. Не трогая панель, осмотреть поле и счётчик.
3. Нажать кнопку подтверждения повторно.

**Ожидаемый результат фиксирует текущее поведение:** после шага 1 поле сохраняет
введённое значение, счётчик остаётся равным `3`. Повторное нажатие на шаге 3
добавляет тот же товар ещё раз — количество в строке становится `6`.

**Риск:** отсутствие сброса провоцирует случайный повторный клик и незаметное
удвоение заказа. Если продукт начнёт очищать поле и счётчик после добавления —
ожидаемый результат этого сценария нужно переписать.

**Уборка:** удалить добавленную строку.

### BASKET-007. Изменение количества в строке и пересчёт суммы

**Предусловие:** в корзине есть `4610495` с количеством `3`, позиция отмечена.

1. Запомнить цену товара и текущую сумму выбранных.
2. Нажать `−` в строке товара.
3. Сверить количество и сумму.
4. Нажать `+` в строке товара.

**Ожидаемый результат:** количество меняется `3 → 2 → 3`; сумма выбранных
пересчитывается сразу и на каждом шаге равна «цена × количество». Возврат
к исходному количеству возвращает исходную сумму.

**Уборка:** удалить добавленную строку.

### BASKET-008. Недопустимое количество отвергается

**Предусловие:** в корзине есть `4610495` с количеством `2`.

1. Очистить поле количества в строке и ввести `0`.
2. Перевести фокус из поля.
3. Довести количество до `1` кнопкой `−`.
4. Нажать `−` ещё раз.

**Ожидаемый результат:** ноль не принимается — значение возвращается к `1`.
На шаге 4 количество остаётся `1`: ниже единицы не опускается, строка при этом
**не удаляется**.

**Уборка:** удалить добавленную строку.

### BASKET-009. Массовый выбор `Вибрати всі`

**Предусловие:** в корзине есть хотя бы одна отмеченная позиция.

1. Запомнить текущую сумму выбранных.
2. Снять флажок `Вибрати всі`.
3. Сверить состояние чекбоксов строк и сумму.
4. Установить флажок `Вибрати всі` обратно.

**Ожидаемый результат:** снятие флажка снимает выбор со складских позиций,
сумма выбранных становится `0.00 грн`. Повторная установка возвращает выбор
и исходную сумму. Строки раздела `Товари під замовлення`, которыми этот флажок
не управляет, менять состояние не обязаны.

**Уборка:** восстановить исходное состояние чекбоксов.

### BASKET-010. Несуществующий товар

**Предусловие:** корзина в известном состоянии, состав зафиксирован.

1. Ввести в поле добавления `zz-no-product-987654321`.
2. Нажать подтверждение.
3. **Сразу** осмотреть область уведомлений.

**Ожидаемый результат:** позиция не добавляется, состав корзины не меняется.
Появляется тост с классом ошибки: заголовок `Кошик`, текст
`Товар не знайдено zz-no-product-987654321`.

> Тост живёт **меньше пяти секунд**. Проверять его нужно сразу после нажатия,
> иначе сценарий ложно «пройдёт» на исчезнувшем сообщении.

### BASKET-011. Удаление позиции

**Предусловие:** в корзине есть чужие позиции и добавленный `4610495`.

1. Записать состав корзины и количества всех строк.
2. Нажать кнопку удаления в строке `4610495`.

**Ожидаемый результат:** строка исчезает **сразу, без диалога подтверждения**.
Карточка `4610495` отсутствует; состав и количества остальных строк не изменились.

### BASKET-012. Очистка корзины

**Предусловие:** в корзине есть хотя бы одна позиция.

1. Убедиться, что кнопка очистки отображается.
2. Нажать кнопку очистки корзины.

**Ожидаемый результат:** корзина очищается целиком **без диалога подтверждения**.
Обе секции показывают сообщения о пустом состоянии, сумма выбранных равна
`0.00 грн`, счётчик корзины в шапке обнуляется.

> **Кнопка очистки отсутствует в интерфейсе, когда корзина пуста** — поэтому
> шаг 1 обязателен, а сценарий нельзя начинать с пустой корзины.

> **Разрушительный сценарий.** Кнопка удаляет все позиции, включая чужие,
> и подтверждения не запрашивает. Выполнять только на корзине, состав которой
> не жалко потерять. Позиции раздела `Товари під замовлення` восстановлению
> в исходном виде не подлежат: повторное добавление создаёт строку с текущими
> складом и датой, а не с исходными.

## Постусловие для всех изменяющих сценариев

После выполнения сценария в корзине не должно остаться товаров, добавленных этим
сценарием. Проверяется явно: искомая карточка отсутствует, а число строк совпадает
с зафиксированным до начала. Уборка выполняется и в случае падения сценария
на середине.

## Известные особенности интерфейса

Влияют на формулировку шагов и на автоматизацию:

- кнопки создания счёта не имеют атрибута `disabled` — блокировка зашита
  в обработчик и срабатывает только на **пустую корзину**, а не на пустой выбор;
  при нуле выбранных позиций кнопки остаются кликабельными;
- уведомления об успехе и об ошибке показываются одним и тем же механизмом
  тостов и живут несколько секунд;
- цена и остатки динамические, названия складов меняются — фиксировать
  их точными значениями нельзя.

### BASKET-013. Товар под заказ из окна «Залишки»

Товар без остатка на складах **нельзя** добавить полем `Додати позицію` — он
кладётся в корзину из окна остатков.

**Предусловие:** товара `614 065 0004` («Фільтр масляний», MEYLE) в корзине нет.

1. Найти товар `614 065 0004` через строку поиска в шапке.
2. В строке результата нажать `див. наяв.`.
3. В открывшемся окне `Залишки` найти блок `Під замовлення на склад Омеги`.
4. У первой поставки нажать иконку корзины.
5. Закрыть окно крестиком и перейти в корзину.

**Ожидаемый результат:** позиция появилась в корзине под номером карточки
`46001179890`, ровно одной строкой, в разделе `Товари під замовлення`.

> В том же ряду стоит кнопка `Відвантажити` — она создаёт реальный документ
> отгрузки. Не нажимать.

**Уборка:** удалить добавленную строку.

### BASKET-015. Создание счёта с резервом

**Предусловие:** пользователь работает под выделенным тестовым клиентом. Карточка
`4610495` (`OC90`) уже может находиться в корзине. Её исходное количество, состав
корзины и состояния всех флажков записаны.

1. Снять выбор со всех имеющихся позиций корзины.
2. Добавить ещё одну единицу `OC90` и убедиться, что количество существующей
   строки увеличилось на `1`, а дубль строки не появился.
3. Установить количество строки `OC90` равным `1` — в счёт должна попасть ровно
   одна единица товара.
4. Убедиться, что выбрана только строка `OC90`.
5. Запомнить склады с положительным остатком в порядке таблицы товара.
6. Нажать `У резерв`.
7. В окне `Виберіть склад` выбрать первый склад из запомненного списка и нажать
   `Вибрати`.
8. Дождаться завершения запросов и открытия новой вкладки счёта.

**Ожидаемый результат:** появился один новый номер счёта; в его заголовке указан
статус `Зарезервований`; в составе документа есть карточка `4610495`, а в
заголовке указан выбранный склад.

**Обязательная уборка:** запомнить появившийся номер сразу после создания,
удалить счёт строго по этому номеру и подтвердить удаление. Затем открыть корзину,
удалить тестовый след `4610495`, восстановить её исходное количество и вернуть
исходные флажки всех позиций. Ошибка удаления счёта считается падением сценария.

> Клиент и журнал общие. Нельзя удалять «активный», «последний» или первый счёт
> в таблице без проверки точного номера — это может быть чужой документ.

## Покрытие автотестами

| Сценарий | Автотест |
|---|---|
| BASKET-001 | `BasketOpenTests` — единственный, кто переходит в корзину кликом по шапке |
| BASKET-002…005 | `BasketAddProductTests` |
| BASKET-007…009, BASKET-011 | `BasketRowControlsTests` |
| BASKET-012 | `BasketClearTests` |
| BASKET-013 | `BasketBackorderTests` |
| BASKET-015 | `BasketInvoiceTests` — создаёт резерв и удаляет счёт по точному номеру в `TearDown` |
| BASKET-006, BASKET-010 | не автоматизированы намеренно |

`BASKET-006` фиксирует несброс панели добавления — автотест закрепил бы поведение,
которое похоже на дефект. `BASKET-010` требует ловить тост, живущий меньше пяти
секунд, и пока оставлен ручным.
