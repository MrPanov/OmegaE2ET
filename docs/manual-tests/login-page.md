# Ручное тестирование страницы авторизации

## Общая информация

| Параметр | Значение |
|---|---|
| Объект тестирования | Страница авторизации Omega |
| URL | `https://test.omega.page/#/login` |
| Поддерживаемые браузеры | Chrome, Edge, Firefox |
| Тестовые данные | Действующий пользователь из защищённого хранилища |

Пароли, токены и другие секреты запрещено записывать в этот документ, баг-репорты
и снимки экрана.

## Предусловия

1. Тестовая среда доступна по HTTPS.
2. Есть активный тестовый пользователь.
3. Пользователь вышел из системы, cookies предыдущей сессии удалены.
4. Для негативных проверок используется пользователь, блокировка которого не
   повлияет на других тестировщиков.

## P0 — критический набор

### LOGIN-001. Успешная авторизация

**Шаги**

1. Открыть страницу авторизации.
2. Ввести корректный email.
3. Ввести корректный пароль.
4. Нажать `Увійти`.

**Ожидаемый результат:** пользователь авторизован; открыта основная страница;
доступны элементы интерфейса авторизованного пользователя; пароль отсутствует в
URL и сообщениях интерфейса.

### LOGIN-002. Неверный пароль

1. Ввести email существующего тестового пользователя.
2. Ввести неверный пароль.
3. Нажать `Увійти`.

**Ожидаемый результат:** вход не выполнен; показано понятное сообщение без
раскрытия чувствительной информации; приложение остаётся работоспособным.

### LOGIN-003. Несуществующий пользователь

1. Ввести корректно сформированный, но незарегистрированный email.
2. Ввести произвольный пароль.
3. Нажать `Увійти`.

**Ожидаемый результат:** вход не выполнен; сообщение не позволяет определить,
зарегистрирован ли указанный email.

### LOGIN-004. Оба поля пустые

1. Оставить email и пароль пустыми.
2. Нажать `Увійти`.

**Ожидаемый результат:** запрос авторизации не отправлен; обязательные поля
выделены; показаны понятные сообщения валидации.

### LOGIN-005. Email без пароля

1. Ввести корректный email.
2. Оставить пароль пустым.
3. Нажать `Увійти`.

**Ожидаемый результат:** вход не выполнен; показана ошибка обязательного пароля.

### LOGIN-006. Пароль без email

1. Оставить email пустым.
2. Ввести пароль.
3. Нажать `Увійти`.

**Ожидаемый результат:** вход не выполнен; показана ошибка обязательного email.

### LOGIN-007. Отправка формы клавишей Enter

1. Ввести корректные данные.
2. Нажать Enter в поле пароля.

**Ожидаемый результат:** форма отправлена ровно один раз; результат совпадает с
нажатием кнопки `Увійти`.

### LOGIN-008. Защищённая страница без авторизации

1. В новой приватной сессии открыть URL защищённой страницы.

**Ожидаемый результат:** содержимое не отображается; пользователь перенаправлен
на страницу авторизации.

### LOGIN-009. Завершение сессии

1. Авторизоваться.
2. Выполнить выход.
3. Нажать Back или повторно открыть защищённый URL.

**Ожидаемый результат:** завершённая сессия не восстанавливается; защищённые
данные недоступны.

## P1 — валидация и устойчивость

### Поле email

Проверить следующие значения:

| Данные | Ожидаемый результат |
|---|---|
| `userexample.com` | Ошибка отсутствующего `@` |
| `user@` | Ошибка отсутствующего домена |
| `@example.com` | Ошибка отсутствующего имени |
| `user@@example.com` | Ошибка формата |
| Пробелы до и после email | Обработка согласно требованиям, без неожиданного отказа |
| Пробел внутри email | Ошибка формата |
| Верхний регистр | Поведение согласно правилам учётных записей |
| Очень длинное значение | Контролируемая ошибка, интерфейс не ломается |
| Unicode/кириллица | Контролируемая валидация |
| HTML/JavaScript-строка | Строка не исполняется и не отображается как HTML |

### Поле пароля

- Символы отображаются маской.
- Регистр символов учитывается.
- Пробелы не удаляются незаметно.
- Поддерживаются разрешённые специальные и Unicode-символы.
- Очень длинное значение не ломает страницу и не вызывает зависания.
- Пароль не появляется в URL, ошибках или логах браузера.
- Вставка из буфера обрабатывается согласно требованиям.

### Ошибки и сеть

- После исправления данных сообщение об ошибке исчезает или обновляется.
- Во время отправки виден индикатор выполнения либо кнопка временно недоступна.
- Двойное нажатие `Увійти` не создаёт несколько параллельных авторизаций.
- Ошибки 4xx/5xx показываются пользователю без stack trace.
- При отключении сети форма не зависает навсегда; возможна повторная попытка.
- После восстановления сети успешная авторизация работает без перезагрузки либо
  интерфейс явно предлагает перезагрузить страницу.

## P1 — восстановление пароля и регистрация

### Ссылка `Забули пароль?`

- Открывается правильный экран восстановления.
- Валидируются пустой и некорректный email.
- Результат не раскрывает существование аккаунта.
- Повторный запрос ограничен согласно требованиям.
- Ссылка восстановления имеет ограниченный срок действия и используется один раз.
- Доступен возврат к авторизации.

### Ссылка `Реєстрація`

- Элемент доступен для мыши и клавиатуры.
- Открывается правильная страница регистрации.
- Возврат на login не приводит к ошибке или некорректному состоянию формы.

## P1 — безопасность и сессия

- Используется HTTPS без ошибок сертификата и mixed content.
- Несколько неверных попыток ограничиваются rate limiting или блокировкой согласно
  требованиям.
- SQL injection, XSS и HTML injection не выполняются.
- Сессионные cookies используют необходимые `Secure`, `HttpOnly` и `SameSite`.
- После logout сервер отклоняет старую сессию.
- Поведение параллельных сессий в двух браузерах соответствует требованиям.
- По истечении сессии пользователь перенаправляется на login без раскрытия данных.

Нагрузочные проверки и подбор паролей выполняются только после отдельного
согласования с владельцем тестовой среды.

## P2 — интерфейс, совместимость и доступность

- Tab-порядок: email → пароль → `Увійти` → вспомогательные ссылки.
- У каждого интерактивного элемента виден keyboard focus.
- Форма работает на ширине 320, 768, 1024 и 1920 px.
- Контент остаётся доступным при масштабе 200%.
- Проверены актуальные версии Chrome, Edge и Firefox.
- Текст и сообщения отображаются на согласованном языке.
- Поля имеют программно связанные подписи (`label`/ARIA).
- Документ содержит корректный атрибут языка.
- Email использует подходящую семантику и мобильную клавиатуру.
- Настроены `autocomplete="username"` и `autocomplete="current-password"`.
- Ошибки объявляются программам экранного доступа.

## Регрессионная матрица

| Изменение | Обязательный объём |
|---|---|
| Верстка login | P0 + интерфейс и доступность |
| Клиентская валидация | P0 + email + пароль |
| API авторизации | Весь P0 + ошибки/сеть + безопасность |
| Управление сессией | LOGIN-001, LOGIN-008, LOGIN-009 + безопасность |
| Восстановление пароля | P0 + раздел восстановления |

## Фиксация результата

Для каждого прогона записать дату, окружение, браузер и версию, исполнителя,
статус сценария (`Passed`, `Failed`, `Blocked`) и ссылку на дефект. В дефекте
указать шаги, фактический и ожидаемый результаты, окружение и безопасные
вложения без паролей и сессионных данных.
